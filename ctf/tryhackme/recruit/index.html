Recruit
Write-up

Recruit has just launched its new recruitment portal, allowing HR staff to manage candidate applications and administrators to oversee hiring decisions. While the platform appears functional, management suspects that security may have been overlooked during development. Your task is to assess the application like a real attacker, map its structure, abuse exposed functionality, and exploit vulnerabilities.

Can you gain an initial foothold, escalate your access, and ultimately log in as the administrator?

Let's Go

Nmap Enumeration

Our first task is to scan the target with Nmap and identify the available services. 

nmap -p- -A -sS 10.113.165.77

As shown in the scan results, ports 22/tcp, 53/tcp, and 80/tcp are open.

Exploring the Website

Let's visit the website and inspect its functionality. At the bottom of the homepage, we can see an Account API section.

The Account API exposes a file-related endpoint. Let's keep this information and return to the terminal for further enumeration.

Directory Enumeration

Next, I used Gobuster to discover hidden directories and files. 

gobuster dir -u http://10.113.165.77 -w /usr/share/wordlists/dirb/common.txt

The scan revealed a /mail endpoint. Let's visit it.

Finding the HR Credentials

The mail endpoint contains a log file. Let's inspect mail.log.

The message explains that the HR login credentials are stored in the application configuration file, config.php, for convenience during the initial rollout.

It also states that the administrator credentials are not stored in the application files and are maintained in the backend database.

We can identify the HR username as hr. The next step is to access config.php.

Local File Inclusion

The Account API provided a file-reading endpoint using the file.php?cv=<URL> parameter. First, I tried to access config.html, but the application returned an error stating that only local files are allowed.

In PHP, the file:// URL scheme can be used to access local files on the server. Let's try using it with the same endpoint.

The response reveals the HR password in the HR_PASSWORD variable. With these credentials, we can log in to the application as the HR user.

Initial Foothold

After logging in with the HR credentials, we successfully obtain the first flag.

The dashboard contains a search field and a table displaying candidate IDs. Since the search input appears to interact with the database, SQL injection is worth testing.

Testing for SQL Injection

I started Burp Suite, enabled Intercept, and entered '123 into the search field. The application returned a SQL syntax error.

This indicates that user input is being inserted directly into the SQL query and that the resulting database error is reflected in the response.

I intercepted the request in Burp Suite and sent it to Repeater. Then, I saved the request using the Save item option.

Enumerating the Database

With the saved request, I used SQLMap to enumerate the available databases. 

sqlmap -r sql_ret.txt --dbs --batch --threads=10

The options used above mean:

  • -r sql_ret.txt reads the HTTP request from the file.
  • --dbs lists the databases detected on the target.
  • --batch automatically chooses the default answers.
  • --threads=10 uses ten parallel threads.

The database named recruit_db was discovered, so I focused the next query on that database. 

sqlmap -r sql_ret.txt -D recruit_db --tables

The --tables option lists the tables in the selected database. The results revealed a table named users.

Dumping the Users Table

Finally, I dumped the contents of the users table. 

sqlmap -r sql_ret.txt -D recruit_db -T users --dump

The --dump option retrieves the data from the selected table. The results revealed the administrator's password.

Administrator Access

Using the administrator credentials obtained from the database, I logged in to the application as the administrator.

We successfully obtained the second flag and completed the room.

Conclusion

This room demonstrated how exposed functionality, local file inclusion, weak credential storage, and SQL injection can be chained together to escalate access from a regular HR account to administrator privileges.

Congratulations to everyone who made it this far.
